# V1 — leakage-safe intraday XGBoost

V1 is the first learned model in Multi-Market. It keeps V0 immutable and adds a causal feature layer, expanding-window XGBoost, historical-only confidence calibration, multi-horizon evaluation, non-overlapping execution accounting, historical backfill, and a baseline-aligned time-machine audit.

## Design rules

1. **No future feature leakage.** Features at time `T` use only OHLC bars at or before `T`.
2. **No future label leakage.** A training row becomes eligible only after its entire target horizon has elapsed before the current decision time.
3. **Chronological validation.** The latest historical portion of each expanding training window is held out for probability calibration; random train/test shuffling is never used.
4. **Selective trading.** Raw LONG/SHORT probabilities are calibrated and converted to `NO_TRADE` when confidence is below the threshold.
5. **Realistic account accounting.** Signal-level diagnostics may overlap; portfolio metrics execute at most one position at a time and skip signals that occur while the prior trade remains open.
6. **Frozen V0 comparison.** V1 time-machine tests use exact decision timestamps stored in V0 audit JSON files.

## Features

V1 currently uses 35 causal features:

- returns over 1/3/6/12/24 bars
- realized volatility over 6/12/24/48 bars
- close distance to SMA 6/12/24/48
- close distance to EMA 12/26
- RSI-14
- ATR-14 normalized to bps
- MACD, signal and histogram normalized to bps
- candle range/body/upper/lower wick
- rolling range position 12/24/48
- cyclical UTC time-of-day
- cyclical day-of-week
- London session, New York session, overlap, and U.S. regular-session flags

No news, macro or cross-market features are included in V1; those remain later-version work.

## 1. Freeze V0 time-machine timestamps BEFORE backfill

The current 5,000-row files are the V0 benchmark datasets. Save the deterministic 30-sample audits now:

```bash
for SYMBOL in EURUSD XAUUSD BTCUSD ETHUSD QQQ; do
  multimarket-time-machine "data/${SYMBOL}_5m.csv" \
    --symbol "$SYMBOL" \
    --samples 30 \
    --horizon-bars 6 \
    --lookback-bars 24 \
    --confidence-threshold 0.60 \
    --output-json "reports/${SYMBOL}_V0_TIME_MACHINE_30.json"
done
```

These JSON files freeze the exact decision timestamps used by V0.

## 2. Backfill 5-minute history

Twelve Data supports bounded `start_date`/`end_date` requests but limits each response to 5,000 observations. `multimarket-backfill` therefore uses 14-day chunks and merges/deduplicates them into the existing CSV.

Example one-year backfill:

```bash
multimarket-backfill \
  --symbols EURUSD XAUUSD BTCUSD ETHUSD QQQ \
  --interval 5m \
  --start 2025-08-01 \
  --end 2026-08-22 \
  --chunk-days 14
```

Existing recent rows are preserved and duplicates are replaced by matching timestamps.

## 4. Run one 30-minute V1 evaluation

```bash
multimarket-v1 data/EURUSD_5m.csv \
  --symbol EURUSD \
  --horizon-bars 6 \
  --confidence-threshold 0.60 \
  --min-train-rows 5000 \
  --retrain-every 500 \
  --output-json reports/EURUSD_V1_30M.json
```

The terminal reports signal diagnostics and a separate **non-overlapping execution** section.

## 5. Run 15/30/60-minute suite

On 5-minute bars:

- 3 bars = 15 minutes
- 6 bars = 30 minutes
- 12 bars = 60 minutes

```bash
multimarket-v1-suite data/EURUSD_5m.csv \
  --symbol EURUSD \
  --horizons 3 6 12 \
  --confidence-threshold 0.60 \
  --min-train-rows 5000 \
  --retrain-every 500 \
  --output-json reports/EURUSD_V1_SUITE.json
```

Repeat for the five markets. Do not select a preferred horizon using accuracy alone; compare coverage, selected accuracy, profit factor, expectancy and non-overlapping execution results.

## 6. Re-run the frozen V0 historical timestamps with V1

```bash
multimarket-v1-time-machine data/EURUSD_5m.csv \
  --symbol EURUSD \
  --baseline-json reports/EURUSD_V0_TIME_MACHINE_30.json \
  --horizon-bars 6 \
  --confidence-threshold 0.60 \
  --min-train-rows 5000 \
  --retrain-every 500 \
  --output-json reports/EURUSD_V1_TIME_MACHINE_30.json
```

This is the direct V0 → V1 historical prediction comparison. The decision timestamps are exactly those frozen by V0, while V1 is allowed to learn only from data that occurred earlier than each decision.

## Acceptance philosophy

V1 is **not** accepted merely because one number improves. Evidence should include:

- selected directional accuracy above V0 on frozen time-machine points
- sufficient actionable sample count
- confidence behaving monotonically (higher confidence should generally mean higher hit rate)
- positive or materially improved expectancy after costs
- profit factor above 1 on genuinely out-of-sample periods before paper trading
- non-overlapping execution metrics that are not dominated by one small time window
- robustness across more than one market and more than one historical period

If V1 does not improve out-of-sample results, retain V0 as the benchmark and change V1 rather than tuning the test set.

Historical results do not guarantee future profitability. V1 remains research/backtesting software; it does not place live orders.
